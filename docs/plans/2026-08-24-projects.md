## 1. Current state (investigated 2026-08-24 @ `39054e1`)

### Storage layer — what exists today

**`src/utils/persistence.ts`** (pure functions, node-testable, no Solid coupling):

| Key                                     | Value shape                                                           |
| --------------------------------------- | --------------------------------------------------------------------- |
| `keyforge:doc:v1` (`STORAGE_KEY`)       | `{ version: 1, savedAt: number, doc: AnimationDocument }` JSON string |
| `keyforge:onboarded` (`ONBOARDING_KEY`) | `'1'` once the user has engaged beyond first-run empty state          |

- `serializeDoc(doc)` → wrapped JSON; `deserializeDoc(raw)` → `AnimationDocument | null` via `validatePersisted` (deep v1 validation: doc id/name/duration/layers/tracks/keyframes). The per-doc payload is also what JSON file export/import uses (`DocBar.exportJson` / `importFile`), and import accepts bare docs too.
- All localStorage access is best-effort `try/catch` (storage may be blocked in sandboxed iframes — see note in `easingLibrary.ts`; persistence degrades to a no-op there rather than crashing boot).
- No other keys exist; nothing else in the app reads/writes storage except `easingLibrary.ts`.

**`easingLibrary.ts`** (the one precedent for persisted app state): `@solid-primitives/storage` `makePersisted(createSignal([]), { name: 'keyforge-easing-library', storage: makeObjectStorage(_backingStore) })` — deliberately **in-memory** backing store so it works where localStorage is blocked, explicitly designed to swap to localforage/IndexedDB later with zero API changes ("Phase 4" item in `docs/PLAN.md`: _"Save/load documents (IndexedDB) — swap `makeObjectStorage` → `localforage` in `easingLibrary.ts`"_).

### Store boot & autosave — `src/store/index.ts`

- Module-init boot: `restoredDoc = loadFromStorage()`; fallback `emptyDefaultDoc()` = fresh-nanoid `{ name: 'Untitled', duration: 2000, layers: [] }`. True first run seeds EMPTY so the guided EmptyState fires (audit F21).
- `doc` is a Solid store; **`setDocWrapped` is the single write path** and schedules a debounced (300 ms) autosave; `beforeunload` flushes pending saves synchronously. `flushSave()` = `saveToStorage(serializeDoc(doc))`.
- `replaceDoc(next)` = `setDocRaw(reconcile(next))` + `syncOnboardingFlag()` + immediate `flushSave()`. Callers are responsible for resetting selection/playhead themselves (EmptyState `loadSample`, DocBar CSS/file imports do this).
- `syncOnboardingFlag()` flips `keyforge:onboarded` the first time `doc.layers.length > 0` — every content write funnels through `scheduleSave`/`replaceDoc`, so this stays true with projects as long as autosave remains the funnel.

### UI touchpoints

- **`EmptyState.tsx`**: overlay in the preview area, shown while `doc.layers.length === 0 && !onboarded()`. Two CTAs: "Add your first layer" (`addStarterLayer`) and "Load sample animation" (`loadSample` → `createSampleDoc()` factory from `src/utils/sampleDoc.ts`, `setDoc`, resets selection/playhead, `setPlaying(true)`).
- **`DocBar.tsx`**: header bar with inline rename (live-typing writes `setDoc('name', …)`; blur/Enter commits, blank → 'Untitled'), Export JSON/CSS/CSS·RM, Import file, From CSS… modal (focus-trapped dialog pattern already exists — reusable for any project modal).
- **`App.tsx`**: DocBar renders in the header **desktop-only** (`isMobile()` hides it) — a project switcher living only in DocBar would be unreachable on mobile; must be addressed.
- Existing menu-ish patterns: Inspector stack-picker (`role="menu"`/`role="menuitem"`), native `<select>` for units. No generic dropdown component yet.
- Styles: `.doc-bar*` in `src/styles/app.css`; EmptyState styles in `src/styles/empty-state.css`.

## 2. Recommendation: localStorage multi-key now, IndexedDB later

**Verdict: Phase A ships on localStorage multi-key. Do not introduce IndexedDB/localforage in this feature.**

Reasons:

1. **Doc sizes are tiny.** A rich document is low-KB JSON (the sample ≈ 2 KB serialized). localStorage's ~5 MB budget holds hundreds of projects; quota pressure is theoretical until docs embed assets (they don't — `element.initialCss`/`text` strings only).
2. **Boot is synchronous today.** The store initializes at module import (`restoredDoc = loadFromStorage()`); components render immediately. IndexedDB is async — switching now forces an async boot gate (loading state, Suspense or signal-gated render) through App/DocBar/Preview/Timeline for zero current benefit. localStorage keeps `beforeunload`'s synchronous flush reliable too (an async flush can be dropped by the browser at unload time).
3. **Blocked-context behavior doesn't improve with IDB here.** The sandboxed-iframe concern from `easingLibrary.ts` blocks _both_ localStorage and IndexedDB (opaque origin). Persistence already degrades gracefully; IDB buys no availability.
4. **Zero new dependencies in Phase A.** Matches repo precedent: even the easing library deferred localforage to Phase 4 behind an abstraction seam.
5. **The swap is cheap _if_ we cut the seam now.** Phase A introduces a small storage-port module (§3.1) so Phase B is "reimplement port over localforage + one migration pass", not a rewrite.

**Triggers for pulling Phase B forward:** documents grow binary/large payloads, users report quota warnings, or project count becomes large enough that index rewrites feel wasteful.

## 3. Design

### 3.1 Storage schema (Phase A — localStorage multi-key)

New module `src/utils/projectsStore.ts` (name TBD; pure, node-testable like `persistence.ts`). Three key families:

```
keyforge:projects:index:v1     → ProjectIndex JSON
keyforge:project:<id>:v1       → existing PersistedDoc v1 payload (unchanged shape!)
(keyforge:onboarded            → untouched)
(keyforge:doc:v1               → legacy; read-once during migration, then removed)
```

```ts
interface ProjectMeta {
  id: string // nanoid() from '@/utils/nanoid'
  name: string // unique, case-insensitive (see §3.6)
  createdAt: number
  updatedAt: number
}

interface ProjectIndex {
  version: 1
  projects: ProjectMeta[] // ordered by updatedAt desc (most recent first)
  activeId: string // id of the currently open project
}
```

Per-project values reuse `PersistedDoc { version: 1, savedAt, doc }` **verbatim** — `serializeDoc`/`deserializeDoc`/`validatePersisted` stay untouched, which keeps JSON import/export round-trips and all existing validation tests valid. Only the _addressing_ changes (fixed key → keyed-by-id).

The three operations live behind a narrow seam so Phase B swaps implementations without touching callers:

```ts
// Port interface (sync in Phase A; Phase B makes it async or preloads into memory)
interface ProjectsPort {
  readIndex(): ProjectIndex | null
  writeIndex(index: ProjectIndex): void          // best-effort, try/catch
  readDoc(id: string): AnimationDocument | null  // validatePersisted-guarded
  writeDoc(id: string, doc: AnimationDocument): void
  removeDoc(id: string): void
}
const localStorageProjectsPort: ProjectsPort = /* localStorage impl */
```

### 3.2 Migration of existing autosave

One-time, idempotent, runs inside `readIndex()`/boot:

| State found                                | Action                                                                                                                                                                                                                                                                                                                                                      |
| ------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Legacy `keyforge:doc:v1` present, no index | Create project: `id = nanoid()`, `name = doc.name` (deduped against §3.6 rules), meta stamped; write per-project key + index with `activeId = <newId>`; **remove legacy key after successful index+doc write** (write-ahead order: doc → index → delete legacy). Corrupt legacy payload (`deserializeDoc` → null) → skip creation, seed fresh index (§3.5). |
| Legacy key AND index present               | Migration already ran; ignore/delete stray legacy key.                                                                                                                                                                                                                                                                                                      |
| No legacy key, no index                    | Fresh install → seed (§3.5), never migrate.                                                                                                                                                                                                                                                                                                                 |

Returning-user outcome: their autosaved doc comes back as a named project, active, with layers restored — EmptyState won't re-fire (layers > 0 restores, or flag was set). The onboarded flag needs no migration.

### 3.3 Store API surface (`src/store/index.ts` additions)

The `doc` store **remains THE active document** — every existing mutation, the Preview, Timeline, exports etc. keep working unchanged. Autosave simply learns _where_ to write. New state + API:

```ts
const [projects, setProjects] = createSignal<ProjectMeta[]>([]) // reactive list for switcher/cards
const [activeProjectId, setActiveProjectId] = createSignal<string | null>(null)
```

| Function                           | Behavior                                                                                                                                                                                                                                                                                                                                                                                 |
| ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `listProjects()`                   | Reactive getter → `projects()` (already sorted, most-recent-first).                                                                                                                                                                                                                                                                                                                      |
| `openProject(id)`                  | Flush-save current doc first; `readDoc(id)` → `setDocRaw(reconcile(next))`; set `activeId` in index + signal; reset selection/playhead/playing (centralize the reset currently duplicated in EmptyState.loadSample / DocBar.importFile into one helper, e.g. `resetTransientState()`); update index `activeId`. Missing/corrupt target → keep current doc, surface error (no data loss). |
| `createProject(name?)`             | Unique-name enforcement (§3.6); new nanoid; empty doc `{ id: nanoid(), name, duration: 2000, layers: [] }`; persist doc+index; open it (same path as `openProject`).                                                                                                                                                                                                                     |
| `renameProject(id, name)`          | Uniqueness-checked; updates meta.name in index; if renaming the active project also `setDocRaw('name', name)` so DocBar reflects it. **DocBar's inline rename switches from raw `setDoc('name')` to this** so index and doc never diverge. Blank → 'Untitled' (existing rule).                                                                                                           |
| `deleteProject(id)`                | `removeDoc(id)` + drop from index. If deleting ACTIVE: confirm (UI-side), then activate next most-recent remaining project, or `createProject('Untitled')` if none left — the app is never left without an active project.                                                                                                                                                               |
| `duplicateProject(id)` _(stretch)_ | Deep-copy doc with all-fresh ids (reuse factory discipline from `sampleDoc.ts`), name `<name> copy` (deduped). Cheap win for a v1.1.                                                                                                                                                                                                                                                     |

**`replaceDoc` relationship:** unchanged signature and role — "replace contents of the _active_ project" (file import, From-CSS import land in the currently open project; autosave persists them there immediately). The sample flow is the one place that instead creates its own project (§3.5).

**Autosave interplay:** `flushSave()` becomes `port.writeDoc(activeProjectId(), serializeDoc(doc))` + bump that meta's `updatedAt` (+ move-to-front in `projects()`). Index writes ride the same debounce; `beforeunload` flush keeps working because everything stays synchronous. If `activeProjectId()` is somehow null (shouldn't happen post-boot), fall back to legacy `saveToStorage` — belt-and-braces against losing a save during a botched upgrade.

### 3.4 Built-in sample project on first run

First-run seeding (no index, no legacy key) creates **two** entries in the initial index:

1. `Untitled` — empty doc, **active** (preserves audit F21: guided EmptyState still fires for brand-new users).
2. `Sample animation` — materialized eagerly via `createSampleDoc()` (~2 KB cost; trivial), listed in the switcher and EmptyState cards from the start. This is the owner's "sample animation becomes one such project."

Opening the sample goes through `openProject` → layers > 0 → existing `syncOnboardingFlag` marks onboarded naturally; playback autostart moves from EmptyState's `loadSample` into the sample-open path (or a `playbackHint` flag on the card click) so opening from the switcher behaves consistently. Deleting the sample is allowed; when absent, EmptyState's sample CTA re-registers it via `createProject`-with-preset-doc (factory gives fresh ids, so re-creation never collides). No `builtin` flag needed in v1 metadata.

### 3.5 Boot sequence (rewritten store init)

```
index = migrateAndReadIndex()          // §3.2; seeds Untitled + Sample on true first run
active = index.activeId
doc   = createStore(port.readDoc(active) ?? emptyDefaultDoc())
projects/activeProjectId signals ← index
onboarded signal ← hasOnboarded()      // unchanged
```

### 3.6 Names & edge cases

- **Uniqueness:** case-insensitive compare on trim; creating/renaming/duplicating to an existing name appends `" 2"`, `" 3"`… automatically (no modal nagging) — same spirit as the easing library's upsert-by-name but stricter since names are identities here. `slugify` stays export-filename-only.
- **Deleting the active project:** confirmation dialog (reuse the focus-trap modal pattern from DocBar's CSS import), then auto-open next-most-recent; never a doc-less app.
- **Corrupt per-project doc** (`validatePersisted` null): show it greyed-out in the switcher as unrecoverable, allow delete; don't crash boot.
- **Corrupt index:** treat as absent → run migration path (legacy key will be gone, so fresh seed). Slightly lossy but bounded; acceptable for v1.
- **Storage quota (`QuotaExceededError`):** keep today's silent-swallow baseline in the port, add `console.warn` with key name; writes are ordered doc-before-index so a partial failure leaves the previous good doc readable. Optional stretch: non-blocking toast "Couldn't save — storage full". Real fix is Phase B.
- **Multi-tab:** out of scope for v1 (single-user tool, same risk profile as today's single-key autosave). Note in code; `storage` event syncing is a stretch.
- **Mobile:** DocBar is desktop-only — ship a minimal entry point on mobile (project button on the Layers tab header or top of MobileTabs) in Phase A, full parity later.
- **Export/import interplay:** unchanged — files carry `{version:1, savedAt, doc}`; importing lands in the active project (rename suggestion if name collides is a stretch).

### 3.7 UI placement

**Primary: DocBar dropdown (switcher).**

- The current doc-name span becomes `[project chevron] [name]` — clicking the chevron/name-left opens a `role="menu"` listbox: rows = project name + relative updated-time, check mark on active, hover actions Rename / Duplicate / Delete, footer buttons "+ New project". Keyboard: arrow navigation, Enter selects, Escape closes restoring focus (contract established by #48/#64).
- Inline rename input (existing UX) repurposed to call `renameProject`.
- Rationale: matches the owner's "multiple named documents" mental model; DocBar already owns document identity + import/export; no new layout surface.

**Secondary: EmptyState project cards.**

- Under the existing CTAs, a "Your projects" grid of cards (name + updated time) shown whenever EmptyState renders — satisfying the owner's hint that projects are selectable _at the empty state_. Click = `openProject`. Card count capped visually (scroll) since EmptyState is an overlay.
- "Load sample animation" CTA text becomes "Open sample animation"; it opens-or-recreates the sample project (§3.4) instead of blind `setDoc`.
- Post-onboarding deliberately-empty doc keeps the quieter canvas hint (audit F19/F21 semantics preserved); switcher in DocBar covers navigation there.

### 3.8 Onboarded-flag interaction

No schema change. Semantics hold because: flag still flips only when content appears (`syncOnboardingFlag` runs inside scheduleSave/replaceDoc, both preserved); migration preserves flag + content together so returning users aren't re-nagged; first-run still boots into empty Untitled with flag unset → EmptyState shows with project cards beneath (cards are inert data, they don't count as "engagement"). Opening sample/creating a project sets content → flag flips → subsequent deliberate empties show canvas hint, not welcome copy. One nuance: `openProject` to an empty project post-onboarding shows the hint, not the guided card — correct by design.

## 4. Phased delivery

### Phase A — Projects on localStorage multi-key _(this plan's implementation scope)_

1. **A1 — Persistence core** (pure, tested): `projectsStore.ts` with `ProjectsPort`, `localStorageProjectsPort`, index CRUD helpers, unique-name helper, `migrateLegacyDoc()`. No store wiring yet.
2. **A2 — Store integration**: boot rewrite (§3.5), signals, `listProjects/openProject/createProject/renameProject/deleteProject`, autosave retarget, `resetTransientState()` extraction, `replaceDoc` retarget. Existing tests green.
3. **A3 — DocBar switcher**: chevron + menu, rename wiring, delete-with-confirm, New project. Desktop.
4. **A4 — EmptyState cards + sample-as-project**: card grid, CTA retext, sample registration/seeding, mobile reachability minimum.
5. **A5 — Polish**: duplicate (stretch), quota warning toast (stretch), docs/PLAN.md checkbox updates (note "documents done early; IndexedDB swap remains").

Ship A1–A4 as one PR-sized unit if review appetite allows; otherwise A1+A2 / A3+A4 split.

### Phase B — IndexedDB swap (completes PLAN.md Phase 4 item)

1. Add `localforage` (≈ 9 KB gz) — the only dep either phase adds.
2. `idbProjectsPort`: same port methods, async. Two options, decide at implementation time:
   - **B-async**: make port async + preload index/docs into memory at boot behind a tiny loading gate (recommended: simplest correctness story);
   - **B-sync-mirror**: load everything into memory at boot and treat IDB as a write-behind log (keeps sync reads; weaker durability guarantees).
3. One-time migration: localStorage index + docs → IDB, verify counts, then clear localStorage keys (keep `keyforge:onboarded` — it's a flag, leave it).
4. Swap `easingLibrary.ts` `makeObjectStorage(_backingStore)` → `localForage` driver (the original PLAN.md line item) in the same PR.
